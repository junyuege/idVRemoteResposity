# 加页手记攻略项目规划

## 产品定位

这是一个面向第五人格玩家的微信小程序查询工具。核心目标是在对局准备和路线复盘时，用尽量少的点击找到对应攻略图。

核心路径：

`首页地图/作者 -> 路线查询（版本、形状、入口） -> 攻略图片`

辅助能力包括异象、道具、辞章图鉴，小抄教学，意见反馈和项目说明。

## 当前架构

- `data/localMapIndex.js`：地图、版本、形状、侧门、图鉴的唯一数据源。
- `data/api.js`：页面统一读取接口，同时处理云素材和本地素材回退。
- `pages/`：主包页面，负责查询流程和通用功能。
- `pages/explorer/`：在单页内完成版本切换、形状选择和侧门选择。
- `pkg-*/assets/`：按作者和路线拆分的攻略图片分包。
- `data/cloudAssets.js`：云文件 ID 映射；云能力不可用时回退本地分包。
- `cloudfunctions/addFeedback/`：反馈入库云函数。
- `tools/`：素材同步、云映射生成和项目完整性检查。
- `project.config.json`：发布时排除 `tools/` 素材缓存和项目文档，避免占用主包体积。

## 体验原则

1. 查询优先：首页直接提供难度快捷入口，层级页只呈现当前决策需要的信息。
2. 减少跳转：版本、形状和侧门选择保持在同一页面，旧页面仅作为兼容入口。
3. 状态明确：加载、空数据、参数错误、图片失败和提交中均有独立状态。
4. 内容可扫读：路线与图鉴使用稳定尺寸列表，长名称不挤压关键操作。
5. 弱网可用：攻略图同时保留云存储和本地分包来源。
6. 新数据低成本：新增作者或版本主要更新索引和素材，不复制页面逻辑。

## 多作者数据约定

每条路线必须声明以下字段：

- `id`：全局稳定的唯一 ID，例如 `lianghapi-v0710`。
- `legacyIds`：兼容旧分享链接的 ID 列表；新路线可以为空数组。
- `difficulty`：只用于难度排序和样式，例如 `easy`、`hard`、`special`。
- `authorId` / `author`：稳定英文作者 ID 和中文展示名。
- `packageRoot`：本地兜底分包，例如 `pkg-lianghapi-v0710`。
- `assetNamespace`：云存储目录，例如 `maps/e_yun_zhi_nv/lianghapi/v0710`。
- `legacyCloudPackage`：旧云目录兼容字段；新作者首次导入时不需要。
- `entryMode`：可选。`fileIcons` 表示该路线按单张攻略图显示对应识别图标入口。
- `iconPackageRoot` / `iconNamespace`：逐图图标模式的本地分包和云目录。

不要让不同作者复用相同的路线 `id`、`packageRoot` 或 `assetNamespace`。
只有确认旧云目录从未被其他路线共用时才能填写 `legacyCloudPackage`；展十版两条困难路线不复用旧 `pkg-hard`，以免同名文件串版。

## 新增作者流程

1. 在地图的 `authors` 中登记稳定的作者 ID 和展示名。
2. 在 `routes` 中加入路线数据，并完整填写上述多作者字段。
3. 运行 `node tools/sync-assets.js` 生成独立本地分包（路线图统一输出 `.jpg`）。
4. 在 `app.json` 注册新分包的占位页面。
5. 将该路线 `packageRoot/assets` 内的图片上传到云存储的 `assetNamespace` 目录。
6. 确认云文件全部存在后运行 `node tools/gen-cloud-assets.js` 生成映射。
7. 运行 `node tools/validate-project.js`，再完成开发工具预览和真机检查。

`gen-cloud-assets.js` 只生成 fileID 映射，不负责上传文件。不要在云文件尚未上传时运行并发布新映射。

## 版本路线图

### P0 稳定性与发布基线

- 每次素材更新后运行 `node tools/validate-project.js`。
- 在微信开发者工具完成主流程、真机图片、分享路径和反馈云函数检查。
- 只有图片、索引、云映射三者一致时才发布。

### P1 内容维护

- 为版本增加更新时间、适用游戏版本和变更摘要。
- 凉哈皮版 `v0710` 已作为第二位作者开放；后续按相同字段约定增加路线。
- 统一攻略作者标识和授权说明，避免名称散落在页面逻辑中。

### P2 查询效率

- [x] 增加最近查看，允许一键返回上次路线。
- [x] 增加路线形状和侧门名称搜索。
- 为图鉴增加品质和刷新难度筛选。

### P3 运营与质量

- 记录匿名页面访问、图片失败和无结果搜索，用于排序内容维护优先级。
- 建立反馈处理状态，区分待确认、处理中和已解决。
- 数据规模明显增长后，再评估后台内容管理系统；当前继续保留代码生成索引。

## 发布检查表

1. 运行 `node tools/validate-project.js`，必须零失败。
2. 微信开发者工具执行代码质量检查，确认无 WXML/WXSS 编译错误。
3. 走通首页到详情、整图路线、图鉴搜索、详情弹层和反馈草稿。
4. 真机验证云图片、长按图片、全屏预览和分享落地页。
5. 部署 `addFeedback` 云函数并确认 `feedback` 集合写入权限。
